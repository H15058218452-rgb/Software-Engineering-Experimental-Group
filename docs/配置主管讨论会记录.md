## 一、议题与结论

### 1. 仓库唯一
沿用现有 GitHub 仓库 `Software-Engineering-Experimental-Group`，**不新建第二个仓库**，也不用目录代替分支。
迭代 1、迭代 2、迭代 3 的所有基线代码都保存在同一仓库中。

### 2. 分支结构（Git Flow）
| 分支 | 作用 | 写权限 |
|---|---|---|
| `main` | 稳定、可部署、可演示的交付版本 | 仅配置管理员 |
| `develop` | 日常开发集成，全组最新代码 | 仅通过 PR 合并 |
| `topic/姓名` | 成员个人开发分支 | 本人 |

现有 topic 分支：`topic/li-xuanwei`、`topic/du-meifang`、`topic/tong-xinqi`、`topic/chen-zeying`。

### 3. 权限与保护
- `main` 仅配置管理员有写权限，其余成员一律通过 Pull Request 合并。
- 已对 `main`、`develop` 开启分支保护：Require a pull request before merging，禁止绕过。

### 4. 提交信息规范
格式统一为 `<type>(<scope>): <中文说明>`，type 取值 feat / fix / docs / refactor / test / chore。
禁止提交 `target/`、`node_modules/`、`application-local.yml`、`*.log` 等构建产物与敏感配置。

### 5. 智能体（AI）协作约定
- 提交前必须先执行 `git status` 与 `git diff`，确认改动范围。
- 提交信息使用中文规范格式，由本人身份提交，不使用智能体名义。
- 禁止直接 push `main` 与 `develop`。
- 每天开发前先执行 `git fetch origin && git merge origin/develop`。

### 6. 版本与交付
- 版本一律用 tag 标记，禁止用压缩包存档。
- 迭代 2 基线已打标签：`v1.2-iteration2`。
- 评审材料：仓库综述、分支结构图（SourceTree 截图）、本会议记录。
