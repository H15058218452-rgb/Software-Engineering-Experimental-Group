## 二、B.1 订单（杜美芳）

### B.1-1 从购物车下单（5 点）

> 客户想要在购物车勾选多件商品一起提交，以便一次买齐、只产生一笔订单。

验收标准：
- 【已裁定】下单入口**只有购物车**；商品详情页不提供「立即购买」旁路，必须先加入购物车
- 【已裁定】一次提交生成 **1 笔订单**，订单含多条商品明细，不是每件各 1 单
- 【已裁定】**下单即真实扣减库存**：下单成功那刻按明细逐条扣减，被扣部分立即从可售库存消失，其他订单不可再占用
- 【已裁定】下单前逐条校验：任一明细库存不足则**整单不生成**，返回缺货商品清单；客户剔除后重新提交，不做部分成单
- 【已裁定】明细定格下单时的名称、单价、数量、小计；订单记录客户、总金额、下单时间、订单号
- 【已裁定】商品价格发布后不可修改，故明细单价即当前价，不涉及改价或议价
- 【组内拟定】订单号格式 `yyyyMMdd-####`（如 `20261112-0001`），当日流水、全局唯一
- 【组内拟定】下单成功后，本次已下单的购物车项从购物车移除
- 【组内拟定】单笔订单明细上限 20 条（需求未定义，取保守值）
- 涉及数据：`order`（主表）、`order_item`（明细表）

### B.1-2 商家按序推进五个状态（5 点）

> 商家想要在后台一步步推进订单，以便线下备货与交付过程可被记录、可被追溯。

验收标准：
- 【已裁定】状态序列：客户下单 → 商家确认 → 备货完成 → 开始发货 → 交易完成，**必须按序推进**
- 【已裁定】不允许跳态（如「商家确认」直接到「开始发货」）、不允许回退（如确认后退回「客户下单」）
- 【已裁定】五个状态**全部由商家单方推进**；客户侧只能查看，不能推进、也没有「确认收货」动作
- 【已裁定】「交易完成」由商家在线下交易实际完成后手动标记，不是客户确认、不是双方确认，**也无超时自动完成**
- 【已裁定】交易完成为终态，不涉及退货、退款、售后；系统无在线支付
- 【已裁定】系统无定时任务：没有超时自动取消、没有卡单兜底
- 【组内拟定】同一客户可同时存在多笔不同状态订单，数量无上限、无下单频率限制
- 【组内拟定】重复提交同一状态视为非法流转，直接拦截并返回当前状态，不做幂等静默成功
- 错误码：状态非法统一 40921，响应附「当前状态 / 目标状态」

### B.1-3 双向取消订单并回补库存（3 点）

> 客户和商家想要在各自允许的时机取消订单，以便货未交付时及时止损，并把库存让出来。

验收标准：
- 【已裁定】**客户**可在「开始发货」之前取消，即可取消状态：客户下单、商家确认、备货完成
- 【已裁定】**商家**可在「交易完成」之前取消，即可取消状态：客户下单、商家确认、备货完成、开始发货
- 【已裁定】取消后进入独立「已取消」状态，**不与交易完成共用**；已取消是终态，不可再推进、不可再取消
- 【已裁定】取消即时生效，无对方确认、无审批、无二次确认
- 【已裁定】不记录取消原因、不记录取消时间；订单字段中没有这两项
- 【已裁定】已取消订单**出现在买家下单历史中**，最终结果标「已取消」
- 【已裁定】取消是整单取消，不支持只取消其中某几条明细
- 【已裁定】「已取消」不区分是谁取消的，前端统一展示「已取消」
- 【已裁定】取消时**回补库存**：按明细逐条把数量加回商品（因下单已扣，取消必须归还）
- 【已裁定】取消回补把库存加回后，商品**自动回到「在售」**，商家无需任何操作
- 错误码：已取消再操作 40923；取消时机不符 40921；非订单归属方 40922

### B.1-4 买家与商家查看订单（2 点）

> 客户和商家想要查看订单清单与明细，以便知道每笔订单买了什么、进行到哪一步。

验收标准：
- 【已裁定】买家可查看自己的全部订单（含已取消），只读、不可删除
- 【已裁定】订单展示字段：订单号、商品清单（名称 / 单价 / 数量 / 小计）、总金额、下单时间、当前状态、最终结果（交易完成 / 已取消）
- 【已裁定】**订单不记交易地点**；「默认交易地点」只是账号档案，仅商家在客户列表可见
- 【已裁定】不做逐状态时间戳，只有下单时间
- 【组内拟定】列表按下单时间倒序，每页 10 条
- 【组内拟定】不做独立「订单详情页」路由，列表展开即明细
- 【已裁定】卖家**不设全局订单列表、不按状态筛选**；商家从客户详情页查看该客户的订单记录与结果，并在此处推进状态或取消

### B.1-5 商品状态收敛（3 点）

> 作为需求变更的连带改造：订单取代购买意向排队后，商品不再需要「交易中冻结」状态。

验收标准：
- 【冲突已裁定】商品状态由迭代 2 的四态（在售 / 手动冻结 / 交易中 / 已下架）**收敛为两态**：在售、已下架
- 【冲突已裁定】「已冻结（交易中）」废弃，原因：该状态只服务于「意向→排队→冻结」模型，B 用订单取代排队后不存在冻结时机
- 【已裁定】「已下架」非统一终态，按来源打标签：已售、库存耗尽下架、手动下架
- 【已裁定】库存归 0 自动下架，触发包括下单扣到 0、商家手动调 0
- 【已裁定】**订单取消回补**使库存由 0 转正时，商品**自动回到「在售」**，商家无需操作
- 【已裁定】**商家主动补货是两个动作**：先手动调高库存，再手动重新上架，商品才回到在售；补货本身不改商品状态
- 【已裁定】「重新上架」要求商品已下架且库存 > 0
- 【已裁定】商品不能删除，退出在售只有下架一种方式
- 【已裁定】有在途订单时**允许**商家调库存、允许手动下架，在途订单不受影响（库存已于下单时扣出）
- 【已裁定】买家浏览与搜索只展示「在售」；已下架对买家默认不可见
- 说明：本故事由 B.1 引起，属商品模块（杜美芳）职责，禅道未单独立任务

## 三、B.2 收藏与购物车（需求由杜美芳出，实现归李炫苇）

### B.2-1 客户收藏商品（2 点）

> 客户想要把看中但暂不下单的商品收藏起来，以便之后回来找。

验收标准：
- 【已裁定】收藏对象为在售商品；收藏不锁库存、不占位
- 【已裁定】支持添加收藏、取消收藏、查看收藏列表
- 【已裁定】需登录后使用，未登录点收藏引导登录
- 【已裁定】商品下架后收藏项**保留**并标注「已下架 / 无货」
- 【已裁定】收藏列表**不提供**「加入购物车」「直接下单」，只能点进商品详情
- 【已裁定】收藏为账号私有数据，不展示被收藏次数、无对外热度
- 【组内拟定】收藏上限 200 条

### B.2-2 客户使用购物车（5 点）

> 客户想要把多件商品先放进购物车，以便凑齐后一起下单。

验收标准：
- 【已裁定】支持加入购物车、修改数量、移除商品
- 【已裁定】需求未要求「清空购物车」与「全选」按钮，不做
- 【已裁定】同款可买多件，购物车列表有数量字段；上限单条 99 件
- 【已裁定】购物车**不锁库存**、不占位；加购阶段不校验、不设限
- 【已裁定】购物车最多 50 条
- 【已裁定】需登录后使用；未登录加购引导登录
- 【组内拟定】未登录时的临时加购在登录后**自动恢复**到账号购物车（需求方明确希望恢复，避免体验损失）
- 【组内拟定】购物车列表展示：商品名称、单价、数量、小计
- 【已裁定】下架商品在购物车中的处理需求未定义；【组内拟定】保留并标注「已下架」，结算时拦截

### B.2-3 购物车多件结算下单（5 点）

> 客户想要勾选购物车里的多件商品一起提交，以便一次完成多件商品的购买。

验收标准：
- 【已裁定】从购物车选多件一起下单，生成 1 笔含多明细的订单（与 B.1-1 同一能力，不另造订单模型）
- 【已裁定】结算时逐商品校验库存，缺货的单件提示、让客户剔除后重下，不拖累其他商品
- 【已裁定】整单原子性：本次提交要么全部生成，要么全部不生成
- 【已裁定】结算不重复扣库存——扣减只发生在订单创建（B.1-1）内，结算只做组装与校验
- 【已裁定】购物车中已下架商品的明细不可提交
- 【组内拟定】下单成功后移除已下单的购物车项
- 接口边界：结算接口由李炫苇实现，内部调用杜美芳的订单创建接口，**不直接写 `order` / `order_item` 表**

### B.2-4 购物车多件转收藏（2 点）

> 客户想要把购物车里暂时不买的商品批量转为收藏，以便清空购物车但不丢掉看中的商品。

验收标准：
- 【已裁定】支持从购物车选中多件，批量转为收藏
- 【已裁定】转收藏同样受收藏上限 200 条约束
- 【已裁定】转收藏不锁库存、不产生订单
- 【组内拟定】转收藏成功后，原购物车项移除
- 【组内拟定】已在收藏中的商品重复转入不报错，静默保留一条

## 四、全局业务规则

| 项 | 口径 | 标签 |
|---|---|---|
| 卖家模型 | 单卖家自营，所有订单归属唯一卖家账号 | 已裁定 |
| 库存语义 | 非负整数；下单真实扣减；取消回补；归零自动下架 | 冲突已裁定 |
| 商品状态 | 只有在售、已下架两态 | 冲突已裁定 |
| 排队机制 | 购买意向 / 先到先得 / 冻结在 B 中**下线**，由订单取代 | 冲突已裁定 |
| 改单 | 下单后不可改数量、不可部分取消、不可改地址 | 已裁定 |
| 售后 | 无退货、无退款、无售后 | 已裁定 |
| 定时任务 | 无超时取消、无自动完成 | 已裁定 |
| 支付 | 无在线支付，钱货线下交付 | 已裁定 |
| 上限 | 购物车 50 条、收藏 200 条、单条数量 99、订单数不限 | 已裁定 + 组内拟定 |

## 五、本轮明确不做

退货 / 退款 / 售后、下单后改单、部分取消、改收货地址、订单删除、订单号自定义、客户确认收货、超时自动取消、卡单标红提醒、商品删除、收藏直接加购或下单、收藏对外热度、购物车清空与全选、多卖家 / 店铺、发票、评价、消息通知、数据迁移。

## 六、已确认口径（需求方已明确答复）

| # | 事项 | 结论 |
|---|---|---|
| 1 | 排队 / 冻结机制在 B 是否保留 | **整体删除**。意向排队、交易中冻结全部下线，完全由购物车和订单替代 |
| 2 | 库存扣减时点 | **下单即扣、取消回补**；回补后商品自动回到在售 |
| 3 | 商家主动补货 | **两个动作**：先手动调库存，再手动重新上架；补货本身不改状态 |
| 4 | 订单可见范围 | 买家看自己全部订单（含已取消）；商家看每个客户的订单记录，**不做按状态筛选的列表** |
| 5 | 多明细争最后库存 | 因下单即扣，该场景已结构性消除；只保留下单时整单校验
