# 挑战需求 C 用户故事与验收标准

> 适用版本：迭代 4（挑战需求 C：支付升级、配送升级、售后服务升级）
> 角色：客户（买家）、商家（卖家）。单卖家自营，系统不存在管理员角色。

## 0. 通用约定

| 项 | 约定 |
|---|---|
| 订单状态 | 客户下单 → 待支付 → 已支付 → 商家确认 → 备货完成 → 开始发货 → 交易完成；另有终态「已取消」 |
| 终态 | 「交易完成」由客户点击「确认收货」触发；「已取消」后不可再推进 |
| 金额 | 无运费、无优惠，订单金额 = 商品快照单价 × 数量之和；退款按商品金额原路退回 |
| 通知 | 全程无主动通知，支付结果、发货、物流、售后进展均由客户在订单页自行查看 |
| 售后单状态 | 待处理 → 待收货 → 已退款；另有「已拒绝」「已撤销」两个终止态 |
| 库存口径 | 下单时即扣减可售库存（即占用，不够不允许下单），超时或取消时回补；「交易完成」不再变动库存，避免重复扣减 |
| 售后入口 | 从「开始发货」起开放；发货前不开放售后，退款统一走「取消订单」 |

## C.1 支付升级

### US-C1-01 客户在线支付订单

**作为**客户，**我希望**在提交订单后选择支付方式完成付款，**以便**锁定商品、等待商家发货。

**验收标准**

1. 提交订单成功后，订单进入「客户下单」并立即流转到「待支付」，订单页展示商品明细、应付金额与「去支付」入口。
2. 支付页提供银行卡、信用卡、支付宝、微信四个渠道，客户单选其一；不支持同一订单用多种渠道组合支付。
3. 支付成功后，订单状态由「待支付」变为「已支付」，同时记录支付渠道、支付金额、支付时间。
4. 支付金额必须等于订单金额；金额不一致时本次支付不成立，订单保持「待支付」。
5. 同一订单的重复支付结果只生效一次，订单状态与库存不被重复修改。
6. 订单进入「已支付」后，「商家确认」环节保留，需商家手动点击确认，不自动流转。
7. 「待支付」订单在商家后台只能取消，不提供「确认」「备货」「发货」操作。

### US-C1-02 待支付超时自动取消

**作为**系统，**我希望**对待支付订单超时自动关闭，**以便**释放库存、避免长期占用。

**验收标准**

1. 订单进入「待支付」时开始计时，支付时限 24 小时。
2. 超时未支付，系统自动将订单置为「已取消」，取消原因记为「支付超时」。
3. 自动取消的同时回补该订单占用的库存，商品可售数量恢复。
4. 已取消订单不再接受支付，客户进入支付页时提示订单已关闭。
5. 系统不主动通知客户，客户在订单页可看到「已取消」状态与取消原因。

### US-C1-03 支付失败后的处理

**作为**客户，**我希望**支付失败时订单不被关闭，**以便**重新选择渠道完成付款。

**验收标准**

1. 支付失败时订单停留在「待支付」，系统不单独记录「支付失败」状态。
2. 客户可重新发起支付，并可重新选择支付渠道。
3. 重新支付成功后订单正常进入「已支付」，支付记录以成功的那一笔为准。
4. 订单已取消后不允许再次发起支付。

### US-C1-04 客户取消订单

**作为**客户，**我希望**在商家发货前取消订单，**以便**在改变主意时减少损失。

**验收标准**

1. 「待支付」状态客户可直接取消，订单转「已取消」，不产生退款，库存释放。
2. 「已支付」「商家确认」「备货完成」状态客户可取消，订单转「已取消」，款项按原支付渠道退回，库存释放。
3. 「开始发货」及之后，客户无取消入口，界面上不展示取消按钮，接口拒绝该操作。
4. 取消成功后订单进入终态，任何角色都不能再推进或恢复。
5. 取消操作记录操作人、时间与取消原因。

### US-C1-05 商家取消订单

**作为**商家，**我希望**在交易完成前取消订单，**以便**处理缺货、客户要求等异常情况。

**验收标准**

1. 「交易完成」之前（含待支付、已支付、商家确认、备货完成、开始发货），商家均可取消订单。
2. 未支付订单取消不产生退款；已支付订单取消必须按原渠道退款。
3. 「开始发货」后商家取消：订单转「已取消」，款项原路退回，库存不回补（商品已发出）。
4. 取消后客户侧订单页展示「已取消」及取消原因。
5. 交易完成的订单商家不能取消，只能由客户走售后。

### US-C1-06 商家推进订单

**作为**商家，**我希望**按确认、备货、发货的顺序推进订单，**以便**控制履约节奏。

**验收标准**

1. 「已支付」状态可点击「确认订单」，订单进入「商家确认」。
2. 「商家确认」状态可点击「备货完成」，订单进入「备货完成」。
3. 「备货完成」状态可点击「发货」，必须填写物流单号与快递公司（详见 US-C2-03），成功后订单进入「开始发货」。
4. 状态只能按顺序向前推进，不允许跳级，也不允许回退。
5. 每一步记录操作时间与操作人，订单详情可查。
6. 不满足前置状态的按钮不展示或被禁用。

### US-C1-07 客户确认收货

**作为**客户，**我希望**收到货后点确认，**以便**结束订单并进入售后保障范围。

**验收标准**

1. 订单处于「开始发货」时，客户可点击「确认收货」。
2. 点击后订单进入「交易完成」终态，记录完成时间。
3. 系统不做超时自动确认，订单可以长期停留在「开始发货」。
4. 商家不能代替客户确认收货。
5. 「交易完成」后不可取消，只能发起售后。

## C.2 配送升级

### US-C2-01 客户维护收货地址

**作为**客户，**我希望**保存多个收货地址并设置默认，**以便**下单时快速选择。

**验收标准**

1. 客户可新增地址，必填项为收货人、手机号、所在地区、详细地址。
2. 手机号做格式校验，不符合格式不允许保存。
3. 客户可编辑、删除已有地址。
4. 客户可将任一地址设为默认，同一客户同时只有一个默认地址。
5. 每个客户最多保存 10 个地址，超出时提示已达上限。
6. 删除默认地址后，系统自动将最近添加的一个地址设为默认；客户没有任何地址时不设默认。

### US-C2-02 下单选择地址并生成快照

**作为**客户，**我希望**下单时确认收货信息，**以便**商品寄到正确的地方。

**验收标准**

1. 下单页默认带入默认地址，客户可切换到其他已保存地址。
2. 客户没有任何地址时不允许提交订单，引导先新增地址。
3. 下单成功时，收货人、手机号、详细地址写入订单快照。
4. 订单提交后地址不可修改。
5. 客户之后修改或删除地址库中的地址，不影响历史订单的显示内容。
6. 订单详情展示下单时保存的地址快照。

### US-C2-03 商家发货填写物流单号

**作为**商家，**我希望**发货时录入物流信息，**以便**客户能查询物流。

**验收标准**

1. 「备货完成」状态下商家执行发货，物流单号与快递公司为必填项。
2. 未填写物流单号不允许提交发货。
3. 发货成功后订单进入「开始发货」，同时生成该订单唯一的物流记录。
4. 一个订单对应一个物流单号，不拆分包裹。
5. 客户签收前，商家可修改物流单号，修改后客户查询到的是新单号。
6. 发货后订单状态、物流记录、操作时间在同一事务内生效，不出现订单已发货但查不到物流的情况。

### US-C2-04 客户查询物流状态

**作为**客户，**我希望**查看物流单号与运输进度，**以便**知道货到哪里了。

**验收标准**

1. 订单进入「开始发货」后，客户可在订单页看到物流单号与跟踪信息。
2. 物流状态用固定枚举展示：已发货、运输中、已签收。
3. 未发货订单不展示物流入口。
4. 系统不做物流异常预警，也不主动推送物流通知。
5. 物流状态的展示形式（内嵌轨迹或跳转快递页面）以实现为准，不影响本故事验收。

## C.3 售后服务升级

### US-C3-01 客户发起售后申请

**作为**客户，**我希望**对订单中的某件商品发起售后，**以便**解决商品问题。

**验收标准**

1. 可发起售后的订单状态为「开始发货」「交易完成」；「待支付」「已支付」「商家确认」「备货完成」不提供售后入口，退款走取消订单。
2. 售后粒度是商品：客户从订单明细中选择某一件商品，并填写数量。
3. 申请单必填标题与问题描述，图片为选填项。
4. 图片最多 5 张，单张不超过 2MB，格式限 jpg、png、webp。
5. 同一商品同时只允许存在一个进行中的售后单；上一个完结后可再次申请，同一商品累计不超过 3 次。
6. 提交成功后售后单状态为「待处理」，订单状态保持不变。

### US-C3-02 客户查看自己的售后单

**作为**客户，**我希望**查看自己提交的售后单进度，**以便**了解商家处理到哪一步。

**验收标准**

1. 客户只能查看自己发起的售后单，看不到其他客户的。
2. 列表展示商品名称、数量、售后单状态、提交时间。
3. 详情展示标题、描述、图片，以及商家的处理结果。
4. 订单详情页可跳转到该订单关联的售后单。

### US-C3-03 商家查看售后单

**作为**商家，**我希望**集中查看所有售后申请，**以便**逐单处理。

**验收标准**

1. 单卖家模式下，商家可查看全部售后单，不存在按店铺隔离或管理员视角。
2. 列表展示客户、订单号、商品、数量、状态、提交时间，并支持按状态筛选。
3. 详情展示订单信息、商品信息、问题描述与图片。
4. 商家可在列表与详情中执行「同意退货」「仅退款」「拒绝」三个操作。

### US-C3-04 退货退款

**作为**商家，**我希望**在收到退回商品后办理退款，**以便**完成售后。

**验收标准**

1. 商家选择「同意退货」后，售后单进入「待收货」。
2. 客户线下寄回商品，商家在系统中点击「确认收到退货」。
3. 确认收货后，系统按退货件数回补库存（每件 +1），并按原支付渠道退款，售后单转「已退款」。
4. 退款金额 = 该商品下单时的快照单价 × 退货数量。
5. 退款严格原路退回，记录退款渠道与退款时间。
6. 订单状态保持发起售后的状态不变，不新增「售后中」状态。
7. 未点击「确认收到退货」前不产生退款、不回补库存。

### US-C3-05 仅退款不退货

**作为**商家，**我希望**在不需要客户寄回商品时直接退款，**以便**快速了结小额或已损毁的售后。

**验收标准**

1. 商家选择「仅退款」后，无需客户寄回商品。
2. 系统直接按原支付渠道退款，售后单转「已退款」。
3. 库存不回补。
4. 退款金额 = 快照单价 × 售后数量。
5. 订单状态保持不变。

### US-C3-06 商家拒绝售后

**作为**商家，**我希望**拒绝不成立的售后申请，**以便**终止该单。

**验收标准**

1. 商家选择「拒绝」后，售后单转「已拒绝」，订单状态不变。
2. 系统不强制定填写拒绝理由，协商过程在线下进行，系统不留痕。
3. 「已拒绝」的售后单不产生退款、不回补库存。
4. 客户可就同一商品再次申请，但计入累计次数，同一商品累计不超过 3 次。
5. 系统没有商家响应时限，也不会超时自动同意退款或退货。

### US-C3-07 客户撤销售后申请

**作为**客户，**我希望**在商家处理前撤销申请，**以便**在问题自行解决后关闭售后。

**验收标准**

1. 售后单处于「待处理」时，客户可撤销。
2. 撤销后售后单转「已撤销」，不可恢复。
3. 撤销不产生退款、不回补库存，订单状态不变。
4. 撤销后可重新提交申请，计入同一商品的累计次数。

## 附：角色与权限小结

| 操作 | 客户 | 商家 |
|---|---|---|
| 支付订单 | 可 | 不可 |
| 取消待支付订单 | 可 | 可 |
| 取消已支付未发货订单 | 可（退款） | 可（退款） |
| 取消已发货订单 | 不可 | 可（退款，库存不回补） |
| 确认订单、备货、发货 | 不可 | 可 |
| 确认收货 | 可 | 不可 |
| 发起售后 | 可（本人订单） | 不可 |
| 处理售后 | 不可 | 可 |
| 查看售后 | 仅本人 | 全部 |
