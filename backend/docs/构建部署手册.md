# 构建部署手册

> 项目：在线购物系统 MVP（基线需求）  版本：v1.0  日期：2026-10-20
> 组员：杜美芳（后端）、童昕祺（前端买家/卖家端）、陈泽英（前端）、李炫苇（数据库/SQL）、胡芷源（组长/部署）

## 一、环境要求

| 组件 | 版本 | 用途 |
|---|---|---|
| JDK | 17+（编译目标 17，JDK 17~25 均可） | 后端编译运行 |
| Maven | 3.8+ | 后端构建 |
| Node.js | 20+（含 npm 10+） | 前端构建 |
| MySQL | 8.0 | 数据库 |
| Docker | 24+（含 docker compose 插件） | 一键部署（可选） |

## 二、后端构建与运行

```bash
cd backend
mvn clean package -DskipTests     # 构建 jar（产物 target/*.jar）
mvn spring-boot:run               # 或直接开发模式启动
java -jar target/online-shop-backend-1.0.0.jar   # jar 方式启动
```

- 数据库：应用启动时自动建库建表（schema.sql 幂等），连接配置见 src/main/resources/application.yml（默认 root/123456，可用环境变量 SPRING_DATASOURCE_URL / USERNAME / PASSWORD 覆盖）。
- 默认卖家账号：seller / seller123456
- 验证：浏览器打开 http://localhost:8080/swagger-ui.html

## 三、前端构建与运行

```bash
cd frontend
npm install        # 安装依赖（国内可加 --registry=https://registry.npmmirror.com）
npm run dev        # 开发模式，http://localhost:5173（/api 已代理到 8080）
npm run build      # 生产构建，产物在 dist/
npm run preview    # 本地预览构建产物
```

## 四、Docker 一键部署（推荐验收使用）

```bash
docker compose up -d --build      # 构建并启动 mysql + backend + frontend
docker compose ps                 # 查看容器状态
docker compose logs -f backend    # 查看后端日志
docker compose down               # 停止（加 -v 清空数据）
```

启动后访问：
- 前端（买家+卖家统一入口）：http://localhost:5173
- 后端 API / Swagger：http://localhost:8080/swagger-ui.html

说明：三个容器（mysql/backend/frontend）由 docker-compose.yml 编排；后端通过环境变量连接容器内 MySQL；前端 Nginx 反向代理 /api 与 /uploads 到后端。

## 五、Docker 镜像导出 / 推送

方式 A（Docker Hub，需账号）：
```bash
docker build -t <你的DockerHub用户名>/online-shop-backend:latest ./backend
docker build -t <你的DockerHub用户名>/online-shop-frontend:latest ./frontend
docker push <你的DockerHub用户名>/online-shop-backend:latest
docker push <你的DockerHub用户名>/online-shop-frontend:latest
```
验收清单填：<用户名>/online-shop-backend:latest 与 <用户名>/online-shop-frontend:latest。

方式 B（导出 tar 上传网盘，无需账号）：
```bash
docker compose build
docker save online-shop-backend online-shop-frontend -o online-shop-images.tar
# 将 tar 上传百度网盘，验收清单填链接+提取码
```

## 六、常见问题

1. 3306/8080/5173 端口被占用：先停本地 MySQL/后端或修改 compose 端口映射。
2. 后端连不上 MySQL：确认 mysql 容器 healthcheck 通过（docker compose ps 显示 healthy）。
3. 前端构建报 node 版本错误：升级到 Node 20+。
4. 首次启动后端报表不存在：schema.sql 随启动自动执行，重启一次即可。
